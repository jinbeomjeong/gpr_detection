## 2. AIHub 기준 집합

| 검사 | 값 |
|---|---|
| 클래스별 crop | pipe_hyperbola 300 / pipe_band 300 (중복 crop_key 0) |
| 장비 | NM 600 (trainpool의 두 클래스는 전부 NM: 451 / 1,194 키, 비NM 0) |

| 상위 3세션 비중 | hyperbola 217/300 = 72 %, band 245/300 = 82 % |
| 측선(`NM_..._N00_B<n>`) | 151개, 두 클래스가 한 측선에 있는 것 30개 |
| 인접 crop 겹침 | 같은 측선 인접 쌍 중 x 구간이 겹치는 것 108쌍 |

해석
- 봉인: 목록의 모든 파일이 trainpool이고 test 세션은 trainpool 세션과 겹치지 않는다. 문제 없음.
- 쏠림은 풀 자체의 성질이다. hyperbola는 trainpool에 451키뿐이라 300키는 풀의 66 %이고, 세션이 9개뿐이어서 시드를 바꿔도 크게 달라지지 않는다. 단계 A 통계는 크롭 단위 중앙값이라 세션 쏠림의 영향을 받는다. 기준 중앙값은 "상위 세션 몇 개의 질감"에 가깝다는 점을 단계 A 보고에 한 줄 적을 것(세션별 중앙값 분산 보고 권고).
- fold 0이 170장(28 %)으로 크지만 단계 A는 fold를 쓰지 않으므로 영향 없음(기록만).
- 인접 crop 겹침 108쌍은 `aihub_crop_overlap_band` 메모의 성질과 같다(같은 측선 crop이 stride 중앙값 약 103 px로 겹침). 600장은 독립 표본이 아니라 151측선에서 겹쳐 뽑힌 것이다. 중앙값·IQR 산출 자체에는 문제가 없으나 "n 600"을 독립 표본 수로 쓰지 말 것.
- gain 결손: 0.5·0.25 사본이 없는 키가 있다(trainpool NM 전체에서도 gain 0.5 사본이 없는 키 210개). 대비 통계는 gain별 n이 600/544/533으로 다르다. JSON은 gain별 n_images를 이미 기록한다. 결손이 특정 세션에 몰렸는지는 보지 않았다(필요하면 후속).

## 5. 재현성(정적 판단)

- 시드 20261114의 `np.random.default_rng` 하나가 AIHub(hyperbola → band) → 4TU 채움 → IDS 순으로 소비된다. 난수 호출 순서가 고정이고 입력 정렬(`sorted` 키)이 결정적이다.
- 검토 스크립트가 같은 논리를 사본으로 재실행해 세 목록이 행 순서까지 같음을 확인했고, 디스크의 sha도 JSON과 같다(numpy 2.5.4, gpr-dev).
- 의존: 세 목록이 `data/splits/aihub_yolo_v1.csv`, `docs/processing/fourtu_lines_v1.csv`, `docs/datasets/fourtu_duplicate_radargrams.csv`, `data/processing/d3/lines.csv`, 광저우 `radargrams_index.csv` 내용에 의존한다. 이 입력 파일이 바뀌면 같은 시드로도 목록이 달라진다. 그래서 입력 파일 sha를 고정 커밋에 같이 적어 두는 것을 권고한다.
- numpy 메이저 버전이 바뀌면 `Generator.choice`의 스트림이 달라질 수 있으므로(PCG64 자체는 안정적이나 보장 범위 밖) numpy 버전을 같이 기록한다(2.5.4).
