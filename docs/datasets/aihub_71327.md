## 4. lpipe / tpipe 시각 판정

몽타주(원천 `TS_/VS_ B scan_비공동_종배관/횡배관.zip`에서 이미지 12장씩, 세션이 겹치지 않게 시드 20261029로 추출, 빨간 박스=XML 박스, 타일 제목 = T/V·장비·세션 시각):
- `C:\workspace\gpr_detection\data\audit\aihub_71327\montage_lpipe.png`
- `C:\workspace\gpr_detection\data\audit\aihub_71327\montage_tpipe.png`
- 선택한 파일 목록: `data/audit/aihub_71327/montage_picks.json`

판정:
- **lpipe = 수평 띠**. 12장 모두 박스가 폭 100 px 이상, 높이 약 16 px인 가로로 긴 직사각형이고, 내부는 지표 아래 일정 깊이에서 수평으로 이어지는 층 반사다. 쌍곡선 꼬리가 없다. 박스 w/h 중앙값 6.1과 일치한다. 한 이미지에 박스가 2–3개로 쪼개진 경우도 있다(한 층을 이어 붙여 라벨링한 흔적). 측정 방향과 평행한 관로(longitudinal)라는 가설과 부합한다. 수평 띠는 지층 경계·직접파 잔여 반사와 구분이 어렵고, 박스 일부는 지표 근처 잡음 대(clutter) 안에 있다.
- **tpipe = 쌍곡선**. 12장 중 대부분에서 박스 안에 위로 볼록한 쌍곡선(아치)이 보인다. 일부(3–4장)는 신호가 약하거나 clutter에 가려 쌍곡선이 불분명하다. 박스 w/h 중앙값 1.7, 높이 약 27 px이다. 측정 방향과 직교하는 관로(transverse) 가설과 부합한다.
- 결론: 두 클래스를 `pipe` 하나로 합치면 "수평 띠"와 "쌍곡선" 두 모양이 한 클래스에 섞인다. 깊이 추정(쌍곡선 피팅)은 **tpipe에서만 성립**하고 lpipe에는 적용할 수 없다. lpipe 박스는 쌍곡선 피팅 대상이 아니다. 클래스 병합 여부와 깊이 대상 필터링은 cv-detection-expert·gpr-processing-expert가 판단할 일이다.
- 한계: 육안 판정(각 12장)이며 정량 판정(쌍곡선 피팅 성공률)이 아니다.

## 5. 알려진 결함 (이번 감사에서 확인)

1. **XML `<filename>`·`<source>`가 파일명과 불일치**. XML 멤버 이름(=원천 이미지 이름)과 `<filename>` 필드가 다른 경우 1,870건(Training 1,677 + Validation 193; 공동 기타형·대칭형·비대칭형, 맨홀). 원천 JPG 이름 기준으로 `<filename>`에 해당하는 이미지가 없다(`pairing.csv`의 labels_without_image 열). 사례: 멤버 `MA_20171227(115437)_N00_B4_g0.5_x(20293-20549)`의 `<filename>`은 `MA_20181226(153002)_N00_B11_g0.5_x(22064-22320)`, 또 다른 사례는 x 구간이 1 px 어긋남(`9479-9735` vs `9478-9734`). 이 중 XML `<source>`가 멤버 이름의 날짜·시각에서 유도한 세션과 다른 경우는 224건(Training 195, Validation 29; 모두 공동 3종). 변환·분할 스크립트는 **멤버 이름 기준으로 이미지와 짝을 짓고**, 세션 키는 `<source>`를 쓰되 멤버 이름 유도 세션과 대조해 불일치를 기록해야 한다. 어느 쪽 키로 세도 세션 수(1,825 / 1,599 / 교집합 1,599)는 같지만 파일별 소속이 바뀔 수 있다.
2. 라벨 `<filename>`/`<localpath>`를 이미지 이름으로 쓰면 1,870장이 짝을 못 찾는다(원천 이미지 수 = XML 수는 일치).
3. permittivity·scanclass·roadtype이 단일값이라 정보량이 없다.
4. 세션 수가 적은 클래스(lpipe 13, tpipe 11): 세션 단위 분할 시 분산이 크다.
