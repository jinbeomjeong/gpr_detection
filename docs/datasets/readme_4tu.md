## 1. 한 줄 요약

네덜란드 13개 공사현장에서 **500 MHz 공기결합 GPR로 측선을 긋고, 같은 자리를 시험굴착(trial trench)해 실제 관로의 위치·깊이·관종을 기록한** 데이터입니다. 원본은 SEG-Y 원시파일 759개와 "그림으로 그려진" 정답표(png) 125장이라 그대로는 학습에 쓰기 어렵습니다. 이 가공본은 ① 정답표를 전부 CSV로 옮겨 적고, ② SEG-Y를 바로 읽을 수 있는 npy/png로 변환하고, ③ 픽셀을 미터로 바꾸는 물리 파라미터(샘플 간격·속도·지표면 위치)를 파일마다 붙이고, ④ 메타데이터를 한글화한 것입니다.

**가장 큰 가치: 쌍곡선(hyperbola)의 꼭짓점 깊이를 실제 굴착 깊이와 비교할 수 있는, 국내에는 없는 공개 데이터**입니다. 탐지 모델의 깊이 추정 정확도 검증, 전처리(time-zero·속도 추정) 파이프라인 시험대로 쓰기에 적합합니다.

## 4. 물리 축척(픽셀 → 미터) — 반드시 읽을 것

모든 값은 radargrams_index.csv와 각 PathN.json에 파일별로 들어 있습니다.

| **파라미터** | **값** | **비고** |
|---|---|---|
| 트레이스 간격 trace_dx_m | **0.02 m** | 원본 Readme. 바퀴 엔코더 구동 |
| 샘플 수 n_samples | **512** | 전 파일 동일 |
| 샘플 간격 dt_ns | **0.098 ns**(674개, 시간창 50 ns) / 0.195 ns(83개, 100 ns — 현장 11 전부와 09.1·09.2) | SEG-Y 바이너리 헤더(피코초 단위)에서 읽음. 예외: 09.4 Path1·09.6 Path4는 0.117 ns(60 ns), 09.5 Path8·Path13은 헤더 유전율이 2.03으로 비정상 기록 |
| 지표면 샘플 t0_sample_est | 파일마다 자동 추정(15\~99, 중앙값 43) | 처음 100샘플 중 평균 진폭이 최대인 샘플. 같은 활동 안에서도 직접파(약 20대)와 지표면 반사(약 40대) 사이를 오가는 경우가 있어 **활동별 중앙값 `t0_sample_act_median`을 함께 기록**. **자동 추정값이므로 정밀 작업 전 눈으로 확인** |
| 비유전율 eps_r_used | 활동별 8.16\~19.46 | Metadata.csv의 "Ground relative permittivity"(현장 조사자가 활동별로 기록). SEG-Y 텍스트 헤더의 E=(7/9/11, 장비 설정값)는 eps_r_header로 따로 둠 |
| 전파속도 velocity_m_per_ns | 0.3 / √εr | 예: εr=9 → 0.100 m/ns |
| 샘플당 깊이 depth_per_sample_m | dt × v / 2 | 예: 0.098 ns × 0.1 / 2 = 0.0049 m |
| 최대 깊이 depth_max_m | (512 − t0) × 샘플당 깊이 | 50 ns 창·εr=9 → 약 2.3 m |

깊이 환산식:

```
depth[m] = (sample − t0_sample_est) × dt_ns × (0.3 / √eps_r) / 2
distance[m] = trace_index × 0.02
```

> 메인 세션 주(2026-10-29, 원문 아님): 공기결합 안테나이므로 영점은 **지표 반사 샘플**로 잡아야 한다. `t0_sample_est`가 직접파(~20번대)로 잡힌 파일에 이 식을 쓰면 공기 왕복 시간이 토양 속도로 환산돼 깊이가 과대된다(εr 9, h 0.3 m에서 약 +0.1 m). 근거: `docs/research/depth_physics.md` §7.

주의할 점

- 공기결합 안테나라 radargram 맨 위에 **공기층(air gap)** 이 보입니다. t0은 "지표면 반사"를 잡은 것이므로 그 위 구간은 깊이가 음수입니다
- **지표면 위치·유전율이 틀리면 깊이가 통째로 어긋납니다.** 정답 깊이와 비교할 때는 먼저 몇 개 활동에서 쌍곡선 꼭짓점을 실측 깊이에 맞춰 t0·εr을 재보정하길 권합니다(속도 추정 자체가 좋은 연습 문제입니다)
- 트레이스 헤더의 GNSS 좌표는 측선 내내 거의 상수라 **위치로 쓸 수 없습니다**(원본 결함)

## 5. 정답(ground truth) 해석

### 5-1. 원본 정답표가 뜻하는 것

02_정답표_원본PNG\{활동}_ground-truth.png는 시험굴착 구덩이의 **횡단면 그림**입니다.

- 왼쪽 세로선 = 굴착 시작점(Start trench, 거리 0.00). 위 가로선 = 지표면. 그 위 글자(Road, Sidewalk…)는 지표 유형
- 동그라미·점 = 관로 단면(크기는 관경을 대략 반영), 색 = 관종
- 아래 표: **Distance in meters = 굴착 시작점에서 관로까지의 수평거리, Depth in meters = 지표면에서 관로까지의 깊이**, Discipline = 관종 코드
- 오른쪽 사진 = 굴착 현장, 빨간 선으로 관로 지시
- {활동}_survey_map.png = 측선(Path1…PathN)의 배치와 굴착 구덩이 방향(빨간 점선 "Orientation of trial trench")

### 5-2. utilities_groundtruth.csv 열

| **열** | **설명** |
|---|---|
| activity_id, site, activity_no | 활동 ID와 분해값 |
| trench_no | 굴착 번호. 거의 1, 011.7만 굴착 2곳(1·2) |
| seq | 표 안 순서(왼쪽→오른쪽, 1부터) |
| distance_m | 굴착 시작점 기준 수평거리(m). 빈칸 = 원본에 없음. 0.00-1.36처럼 범위 = 슬래브 등 폭이 있는 물체 |
| depth_m | 지표면 기준 깊이(m). 빈칸 = 원본에 없음 |
| code | E 전력, T 통신, W 상수, S 하수, OGC 가스·유류·화학, U 불명, X 관로 아님(콘크리트 등) |
| discipline / 관종 | 코드의 영문·한글 |
| note | 특이사항(범위 표기, 원본 오타 보정, 글자와 색이 다른 경우, "with shield" 등 원문 부기) |

### 5-3. 꼭 알아야 할 한계

1. **깊이 기준(관 상단인지 중심인지)이 원본에 명시돼 있지 않습니다.** 그림상 동그라미 중심에 점선이 걸려 있어 중심으로 보이지만, 소구경 케이블은 차이가 없고 대구경 하수관은 수십 cm 차이가 날 수 있습니다. 비교 시 오차 허용폭에 반영하세요
2. **어느 측선(PathN)의 몇 m 지점이 굴착 단면인지는 기록이 없습니다.** survey_map의 화살표 방향과 굴착 방향, 그리고 radargram에서 쌍곡선이 나타나는 순서로 사람이 대응시켜야 합니다. 측선은 보통 관로와 직각이므로, 한 활동의 모든 측선에 같은 관로가 비슷한 깊이로 반복해 나타납니다 → 깊이 비교는 측선별로 가능하고, 수평 위치 비교는 어렵습니다
3. **번들(bundle)**: 케이블 여러 가닥이 한 묶음이면 표에는 1열이지만 Metadata의 관로 수(Amount of utilities)는 가닥 수로 셉니다. 그래서 두 수가 다를 수 있습니다
4. 정답이 없는 활동 30개(사진만 있거나 관로가 없음)도 radargram은 있습니다 — "관로 없음" 음성 샘플로 쓸 수 있지만, 정답표가 비어 있을 뿐 실제로 관로가 없다는 보장은 없습니다
5. 네덜란드 보도·모래 지반·소구경 케이블 위주라 국내 아스팔트 도로·대구경 관과는 환경이 다릅니다. 사전학습·검증용으로 보고, 국내 실측 데이터로 미세조정하는 용도를 권합니다

### 5-4. 전사 방법과 신뢰도

- 정답표 png 125장을 프로그램으로 읽었습니다(표 격자 검출 → 숫자는 동일 글꼴 템플릿 정합, OCR과 교차 확인 → 관종은 글자 모양+색 판정). 모든 수치가 d.dd 형식 검사를 통과했고, 판독이 애매했던 7건은 사람이 원본과 대조해 확정했습니다(note에 기록)
- 그래도 전사 오류 가능성은 0이 아니므로, 중요한 비교에서는 02_정답표_원본PNG를 한 번 열어 보시기 바랍니다

## 7. 사용 예

### 7-1. npy + json으로 읽기 (가장 간단)

```
import numpy as np, json
D = np.load('05_radargrams_npy/01.1/Path3.npy').astype(np.float32)   # [512 샘플, 트레이스]
p = json.load(open('05_radargrams_npy/01.1/Path3.json', encoding='utf-8'))
depth = (np.arange(D.shape[0]) - p['t0_sample_est']) * p['depth_per_sample_m']   # m
dist  = np.arange(D.shape[1]) * p['trace_dx_m']                                   # m
```

06_scripts\example_load.py \<패키지폴더\> 01.1 Path3 을 실행하면 배경 제거 후 정답 깊이선을 겹쳐 보여 줍니다.

### 7-2. SEG-Y를 직접 읽기

원본은 Radar Systems Inc. RadarMap이 쓴 SEG-Y 변종입니다(little-endian, 3200B 텍스트 헤더 + 400B 바이너리 헤더 + 트레이스당 240B 헤더 + int16 512샘플, 시간 단위 피코초). 일반 SEG-Y 라이브러리(segyio 등)는 빅엔디안·마이크로초를 가정해 값이 틀어질 수 있으므로 06_scripts\sgy_radarmap.py의 read_sgy()를 쓰거나 같은 규칙으로 읽으세요.

### 7-3. 학습용 입력

- 03_radargrams_png_raw: 파일별 99.5% 진폭으로 정규화한 8비트 그레이(처리 없음). 세로 512 px = 512 샘플, 가로 1 px = 1 트레이스 = 2 cm. 모델 입력 전 dewow·배경 제거·게인은 각자 파이프라인으로
- 라벨(박스)은 없습니다. 깊이 정답(수평선)만 있으므로, 박스 라벨을 만들려면 04_radargrams_png_view를 보며 쌍곡선 꼭짓점을 표시하는 작업이 필요합니다(권장: 한 활동에서 정답 관로 수만큼 쌍곡선을 찾아 깊이 순으로 대응)

## 8. 권장 활용 순서

1. 04_radargrams_png_view에서 활동 몇 개(예: 01.1, 04.1, 010.14, 011.14)를 열어 정답 깊이선과 쌍곡선 꼭짓점이 맞는지 확인 → 안 맞으면 t0·εr 재보정
2. 쌍곡선 자동 검출(또는 수동 라벨) → 꼭짓점 깊이 vs 실측 깊이 오차 통계(관종·깊이·지반별)
3. 공공측량 작업규정 제186조 기준(깊이 3 m 이하 평면 ±20 cm·깊이 ±30 cm)으로 판정률 산출
4. 국내 실측(GPR, MALA rd3) 데이터가 들어오면 같은 절차로 비교
