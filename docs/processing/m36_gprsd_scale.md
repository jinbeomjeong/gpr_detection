## 2. 식과 기호

$$\tau(u)=\tau_z+\sqrt{h^2+\big((u-u_0)\,g\big)^2},\qquad g=\frac{\Delta x}{\delta_z},\qquad \tau_a=\tau_z+h$$

반경 R을 고정한 식(D2s)은 다음과 같다. R은 피팅 미지수로 넣지 않았다.

$$\tau=\tau_z+\sqrt{(h+R/\delta_z)^2+((u-u_0)g)^2}-R/\delta_z$$

$$v=\frac{2\delta_z}{\Delta t},\qquad \varepsilon_r=\Big(\frac{c\,\Delta t}{2\delta_z}\Big)^2,\qquad s_y=\frac{P}{P^*},\quad s_x=s_y\frac{\delta_z}{\Delta x}=\frac{s_y}{g}$$

| 기호 | 뜻 | 단위 |
|---|---|---|
| $\tau,\tau_a,\tau_z$ | 시각, 꼭짓점, 영점 | 샘플 |
| $u,u_0$ | 트레이스, 꼭짓점 트레이스 | 트레이스 |
| $g$ | 점근선 기울기(곡률). 곡률에서 직접 재는 양 | 샘플/트레이스 |
| $\delta_z$ | 샘플당 깊이 | m/샘플 |
| $\Delta x$ | 트레이스 간격 0.03(문서값) | m |
| $\Delta t$ | A 0.3022 / B 0.2553 | ns |
| $P$, $P^*$ | 반송파 주기, L1 목표 주기 6 | 샘플, px |
| $c$ | 0.299792458 | m/ns |

- 곡률이 재는 것은 **$g$ 하나뿐**이다.
- $\delta_z$는 $\Delta x$에 비례하고, $v$와 $\varepsilon_r$는 $\Delta x/\Delta t$ 조합으로만 정해진다.
- L1에 필요한 것은 $P$와 $g$다. 둘 다 $\Delta x$와 dt에 무관하다($s_x=s_y/g$).

### 7-1. 목적

- M3-3b에서 GPR-SD L1을 두 팔로 만든다.
  - 주 경로: 자료셋 고정 주기
  - 보고 전용 팔: r0 측정 주기(약 51)

### 7-2. 방식 선택(python-expert와 cv-detection-expert가 정함, 권고 A)

- **A(권고, src 변경 없음)**
  - 기존 `make_detection_image(radargram, config, period_samples_override=...)`(`to_image.py` 1165–1194행, `PeriodSource.OVERRIDE`)를 M3-3b 러너가 GPR-SD 측선에만 넘긴다.
  - 값은 실행 설정 파일(봉인 대상)에 `gprsd_period_samples_fixed: 20.0`, 출처 문자열 `"M3-6 D1 (docs/processing/m36_gprsd_scale.md §4 C1)"`로 둔다.
  - `DetectionImage.period_source == "override"`, 플래그 없음.
  - 장점: r0 코드 경로가 그대로라 다른 자료셋 회귀가 없다.
- **B(src 반영)**
  - `to_image.py`에 상수 `DATASET_FIXED_PERIOD: dict[str, tuple[float, str]] = {"gprsd": (20.0, "samples")}`를 추가한다.
  - `PeriodSource.DATASET_FIXED = "dataset_fixed"`를 추가한다.
  - 설정 필드 `period_mode: Literal["measured", "dataset_fixed"] = "measured"`를 추가한다. **기본값 measured**라 r0이 유지된다. `RECIPE_FIELDS`·`M3_2_ASSUMED`에는 넣지 않는다(축척 필드이고 레시피 아님).

  - `DATASET_DEFAULT_PERIOD["gprsd"]` = 51.2(측정 실패 시 대체)는 **바꾸지 않는다**. GPR-SD 측정은 실패하지 않고, T3 기대값이 51.2를 명시한다.
- $\delta_z$
  - C2 잠정이라 `depth_per_sample_m_rough` 0.012를 그대로 쓴다. 변경 코드는 없다.
  - 나중에 바꾼다면 B와 같은 방식(`DATASET_FIXED_DEPTH_PER_SAMPLE`, `VelocityScaleSource.DATASET_FIXED`, 기본은 끔)으로 한다.

  - 열 단위 검사는 전체 0 열 수 하나만 셌다(값 출력 없음).

### 16-5. 문서와 파일의 불일치(보고 전용)

- README·Introduce.txt는 "Each mat … contains three GPR B-scan images collected in parallel", "The samples per trace are 380, and the time window is 97ns"라고 쓴다.
- 실제 파일은 다르다.
  - 한 .mat에 영상이 하나뿐이다. 도로마다 `_1`·`_2`·`_3`의 3파일로 나뉘어 있다.
  - 샘플 수는 321이다.
- 즉 README는 두 곳에서 공개 파일과 맞지 않는다. 이 문장은 2023-02-20 커밋 `04ea5e7`부터 바뀌지 않았다(저장소 git 이력).
- 해석(가정, 판정에 쓰지 않음)
  - README가 내보내기 이전 상태(원 기록이나 3채널 묶음)를 기술한 것이라면, "380 샘플 / 97 ns"는 한 상태를 함께 기술한 값이다. 이 읽기는 B(dt 0.2553)와 맞는다.
  - 그러나 같은 문단이 파일 구조도 틀리게 적었다. 문서 자체의 신뢰도가 낮으므로 A/B 어느 쪽에도 가중하지 않는다.
