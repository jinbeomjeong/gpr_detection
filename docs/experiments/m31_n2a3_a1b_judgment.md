## 3. 공개 사항

1. **기준 파일 sha 두 개.**
   - [P3] §4-1과 G-b1이 고정한 `n2a2_band_aux.json`의 sha256 **bf42403e…6145**는 Windows 작업 트리의 **CRLF** 바이트 값이다.
   - 저장소 blob(c80825e, `.gitattributes` `eol=lf`)은 **LF**이고 sha256은 **356d817a05583b39ef8ca34ef3765948afa2f6b6bdd1bb5d938400e60a14bf50**이다.
   - 작업 트리를 LF로 바꾸면 blob과 바이트 단위로 같다(재확인함). 내용은 같고 줄바꿈만 다르다. 다른 PC에서 다시 받아 G-b1을 돌리면 sha가 달라 실패할 수 있으므로, 재현 시 `--reference-sha256`은 그 환경의 바이트 값으로 확인해야 한다.
2. **C2 문서 변경.** C2(c80825e)는 진단 json 외에 계획 문서도 바꿨다(`git diff --name-only 2e6526d c80825e` = 진단 json, 계획 문서). 바뀐 곳은 §5-3 확정 기록, §7-2 4의 확인 문구, 변경 이력뿐이다. 설정·코드·시험·판정 규칙은 C1과 같다.
3. **CRLF 산출물.**
   - `n2a3_band_aux.json`·`.csv`는 CRLF로 쓰였다(`m110_band_aux` 텍스트 모드 쓰기).
   - band verdict의 `inputs_sha256.band_aux` 1c0fc45c…8b8d는 CRLF 바이트 값이다.
   - 커밋하면 `eol=lf`로 정규화되어 blob 기준 sha가 달라진다. LF 기준 값: `n2a3_band_aux.json` 2ef36ba1785e55db35555b016b26833fa95301b52b18fcb3e291c8f7931c8721, `n2a3_band_aux.csv` f9dc19f14583ee83d1b3871863ac7d43f9fafbba953094065bffa65d413c79f3.
   - 두 verdict json은 LF다: a1 3d8b80a5…e762, band 1ab14faa…aa5f.
4. **band verdict 실행의 dirty true.** `n2a3_band_verdict.json`의 `git.dirty` true는 앞 단계의 미추적 산출물(a1 verdict, band aux) 때문이다. 추적 파일 변경은 0이다(headcheck). 결함이 아니다.
5. **S-1의 범위.**
   - 사전 확인 S-1(32 px 미만 0 %)은 fold 0 학습 영상 2,000장, 맥락 모드 강제, `augment_context_scale` 출력만 본 값이다. 진단에서는 버림이 모두 이웃 출처였다.
   - 실제 학습에서는 중심 출처 버림도 fold당 12–202건 있었다. 진단 표본에 없던 경우가 학습 전체에서 드물게 나온 것이다.
   - 채움 이동·채움 띠·Ultralytics 단계에서 다시 생기는 32 px 미만 band는 설계상 K32 대상이 아니다(K-5). 그래서 S-1은 "맥락 단계 출력"에 대한 보장이고, 학습에 들어간 최종 라벨 전체에 대한 보장이 아니다.
6. **쌍곡선 AP 여유(U3-c 위험).**
   - 쌍곡선 AP50 평균 91.60은 문턱 90.9를 0.70 %p 차이로 넘었다. N2-a′ 여유는 0.71 %p였다.
   - fold 4는 86.94로 문턱 아래다. 판정은 fold 평균이라 A1은 충족이다.
   - [P3] §8 1번에서 예고한 위험(효과 0이어도 약 30 % 확률로 문턱 아래)은 이번에는 실현되지 않았다. 여유는 여전히 작다.
7. **[J1] 해석 정정.** N2-a′ A1 판정서 §4의 "창에 들어온 band의 30.5 %"는 창 단계 입력 전부(창 밖 포함)의 띠 좌표 폭이었다([P3] §1-3). 그 판정서의 A1 결론에는 영향이 없다.
8. **블라인드.** 메인 세션은 종료 줄·headcheck·log_errors·금지어 검사만 보았다. 판정자는 이 판정서를 위해 두 verdict, 5 fold `metrics.json`(last·best crop), `aug_stats.json`, `gpr_train_settings.yaml`, `train_record.json`, 띠 지표 json, 러너 steps json을 열었다.
9. **K32의 비용([P3] §8 3).** 버린 조각 자리에는 보이는 띠가 라벨 없이 남는다. 그 양은 사전 확인 S-4(1.37 % / 1.56 %, 문턱 5 %)로 제한했다.
10. **4/5 fold 조건은 약한 검정이다([P3] §8 5).** 효과가 0이어도 19 % 확률로 통과한다. 이번에는 1/5라 이 약점이 판정에 작용하지 않았다.
11. **D3 경계 오검출은 범위 밖이다([P3] §8 6).** K32는 4TU 내용/패딩 경계 띠 오검출을 겨누지 않았다.
12. **KS 거리([P3] §8 8).** 사전 확인에서 원 crop 띠 폭 분포와의 KS 거리는 0.148 → 0.156으로, 원 분포에 가까워지지 않았다. 판정 조건은 아니다.

### 4-3. 해석 (판정 아님)

- **K32는 띠 재현율을 되돌리지 못했다.** 띠 정답 매칭은 N2-a′와 거의 같다(정검출 1,137 → 1,130, 미검출 841 → 848). 바뀐 것은 띠 오검출(990 → 857)과 정밀도(75.66 → 76.38)다. 짧은 조각 라벨을 버리자 모델이 띠를 덜 내게 되었지만, 놓친 띠를 더 찾지는 않았다.
- 이것은 [P3] §8 7번의 해석대로 "K32 크기의 변화로는 회복하지 않음"이다. K32가 바꾼 라벨은 K32 적용 전 남김(맥락 단계 남김 + K32 버림) band의 약 3.8–5.5 %(학습 실측)였다. 가설 (1)(짧은 조각 라벨이 주 원인)을 기각하지는 않지만, 지지하는 근거도 나오지 않았다.
- 띠 재현율 하락(M1-10·N2-a 약 69 % → N2-a′ 61 %)의 원인 후보 중 남은 것은 다음과 같다.
  - (2) 중심 band 손실: 맥락 모드 5.5–8.7 %
