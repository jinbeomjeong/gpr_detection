Measured on 4TU activities 01.1, 04.1, 010.14, 011.14 with analysis/processing/fourtu_explore.py (doc docs/processing/fourtu_explore.md).

- Zero band is ONE envelope peak in 41/41 windows (no separate direct wave / surface reflection) -> h cannot come from event gap.
- `t0_sample_est` vs `t0_sample_act_median` flips (e.g. 27 vs 39) are the + and - lobes of the SAME band (gap 1.2-1.4 ns, per-trace corr 0.87-0.95), not direct vs surface. Whole index |est-act| clusters at 1.0-1.5 ns, almost none near 1.95 ns. Lobe-vs-envelope phase offset is only -0.7..+0.6 ns (~ +-3.5 cm).
- Discriminator that worked: shift-coherence test (align traces by k * band shift, k=0 stationary / 1 surface / 2 multiple). Main lobes follow the surface (k=1); weak leading lobe (~-1.9 ns) slightly prefers k=0 (direct coupling).
- Refraction QC: straight-ray eps of good 01.1 apexes ~8.7 (= meta 9); any h >= 0.1 m forces eps -> >40. RMS min at h <= 0.1 m for 22/27 apexes. Earlier "4TU h ~0.29 m" premise was withdrawn 2026-11-07 (spec_depth v2.0 §4-4/§12, depth_physics §7-2).
- (2026-11-07 EM verdicts E1–E5, depth_physics §7-2, judged): E1 h <~ 0.1 m is CONDITIONAL — curvature is the only evidence and assumes meta eps 9; with true eps 12-17 h ~0.1 m cannot be excluded (ray theory exaggerates flattening), h 0 vs 0.05 m indistinguishable, h >= 0.3 m excluded. E2a the 0.75/f_c split limit (Ricker 500 MHz) does NOT transfer: 4TU waveform (apex FWHM 2.9-3.8 ns) gives h_sep 0.33-0.53 m, so single band only says h <~ 0.3-0.5 m and the bias_notes bound is 11-13 cm, not 7.5 (code 7.5 kept by user decision, docs only; 7.5 is NOT conservative). E4 single-band zero bias -4..+3 cm, sign unknown (h->0 shallow like ground-coupled), 10-17 cm if E1 fails. E5 the late event on two-event lines is a SUB-SURFACE event, not a large-h surface reflection (early event = same-activity band time); air_surface_late makes those 50 lines 0.06-0.45 m shallow. GT two-event lines: 11 in sites 3/4/6/8/10; site 9 has no GT activity. User decision 2026-11-07: improve the two-event zero rule BEFORE re-evaluation (replaces "flag only").
- eps_r_used == eps_r_header (device default 9) in sites 01/04/010 -> likely not measured. Site 11 (dt 0.195, samples 0-47 muted) eps 15.18 gives apex depths ~0.22 m shallower than GT.
- (2026-10-31 M2-8 prep, all 759 lines) Zero rule: 709 air_single_event, 50 air_surface_late (33 in site 9) -> site 9 is the exception to the "single band" fact. 32 of 125 activities have no usable GT (30 without a GT table + 08.1, 013.6 whose depths are all blank); 93 activities / 388 GT rows remain. Rule-based apex candidates (analysis/processing/fourtu_apex_candidate_select.py) recall only 20/39 hand-picked apex candidates and also land on layer kinks / limb crossings (precision ~half by eye); a V-vs-hyperbola test cannot separate them because real 4TU apexes are shallow and sharp. Use cross-line support (same depth on >= 2 parallel lines) as the filter.
- (2026-10-31 M2-8 run, commit 043d69f) FAIL: pass_b 0.266 (103/388) < random baseline 0.397. Two spec flaws found with analysis/processing/depth_4tu_v1_diagnose.py: (a) box top margin 1.5/f_c + "earliest first peak >= 0.3 Emax" re-seeds 91 % of candidates exactly ~3 ns earlier onto shallow clutter at the box top (-0.12 m); (b) single-linkage 0.10 m chains dozens of per-activity estimates into wide clusters (68 % in clusters > 0.3 m wide). Even with both swapped, candidates stay shallow-biased (-0.15..-0.20 m; layers repeat across lines) and lose to the GT-range baseline (0.62 vs 0.78). Sites 2, 7, 9 have no GT.
- (2026-11-06 M2-9 B) eps_r_used is ONE value per activity (125/125) -> the 15 % meta-eps uncertainty is common-mode across an activity's lines and does not widen cross-line depth scatter (it is cluster bias, item F). White-noise synthetic repeat scatter of the eval path is <= 3 mm (tau sd <= 0.07 ns, zero sd <= 0.009 ns), so a cluster width is set by the sigma_z budget (0.25 ns, upper bound) and the assumed cross-line true-depth spread sigma_g, not by measured noise. Float ties (0.55-0.50 vs 0.60-0.55 differ ~1e-16) need an explicit tie tolerance in 1-D complete linkage.
- (2026-11-07 M2-9 E pre-survey, analysis/processing/m29e_zero_survey.py, no GT depth) 50 air_surface_late lines; h_est > h_max 0.5 m on 21 (site 9: 16, 7: 3, 2: 1, 3: 1) but only ONE is in a GT activity (03.4 Path3). h_est can exceed h_max because the search window starts at the STRONGEST early peak, not the first. Strongest-event index on the 21 lines is 0/1/2 = 8/7/6 -> no single fallback event is physically obvious. The 11 surface_late lines in GT activities all have the first event strongest and h_est 0.30-0.56 m, conflicting with the h <~ 0.1 m curvature evidence; the h_max rule does not catch them.
- (2026-11-07 spec_depth v2.1, spec only, analysis/processing/m29e2_two_event_zero.py) Two-event rule = antenna-height match: known `antenna_height_m` and gap_h >= 0.75/f_c -> event whose gap to the first matches gap_h within 0.5/f_c is the surface; else first event (`air_first_event`). 4TU has no height -> first event. Single-line timing/amplitude cannot separate D+S from band+layer; only the device height can. Rejected: always-first and strongest both 123/129 (M20 +8.60 cm); strongest also fails because an opposite-polarity merged band partly cancels and can be weaker than a strong layer. M20 processed gap is 2.019 ns vs gap_h 1.695 (+0.32 ns, not +0.02). 4TU 50 lines: 15 (all 11 GT + 07.4 x4) first=strongest and within 0.7 ns of same-activity single band; 35 non-GT (site 9, 02.5 P12, 07.1 P2) ambiguous, some weak first events sit 1.5-2.6 ns before the band.
- (2026-11-07 v2.1.1 judged PASS, uncommitted at the time) 50 two-event lines now `air_first_event`, zero 1.40–11.18 ns earlier; single-event 709 lines byte-identical. Candidate selector side effect: its detection floor 0.05*max(per-sample median level) is computed over the search region below the mute, so an earlier mute pulls the strong sub-surface event into the max and deep candidates drop (27 of 78 lost; 06.6 Path10 3 -> 0). Recorded as a limitation, selector NOT changed (would be 4TU-driven tuning). Pre-registration expected two-event md values: 44 unique lines / 227 candidates / 9 GT lines. Committed `depth_synthetic_v1*` outputs were still v2.0 (no R14) at judgment time.
- Per-line Hungarian with dense GT sets (010.14: 19 pipes) is very lenient; always add a random-depth baseline.

**Why:** these overturn assumptions written into spec_depth_v1 and the agent definition; next 4TU work (M2-8) must not re-derive them.
**How to apply:** treat 4TU as `air_single_event` with zero = band envelope peak; label meta t0 as band lobes; never present "late event = surface reflection" as the right 4TU rule (v2.0 code behaviour; v2.1 = height match, 4TU has no height -> first event, implemented and judged 2026-11-07 — confirm it is committed before citing); always qualify h <~ 0.1 m with "curvature only, meta eps 9 assumed"; recheck h/eps on more activities before relaxing the curvature-fit ban.
